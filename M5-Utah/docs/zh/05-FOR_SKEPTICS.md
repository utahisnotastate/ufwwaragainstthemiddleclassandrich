# M5-Utah 怀疑者指南

你提出尖锐问题是合理的。本页直接作答——无需时间线术语。

---

## 简短回答

**本仓库包含两件不同的事：**

1. **创意/科幻档案**（27 个「UFW 武器」、经济讽刺、时间线传说），附带引用虚构库的桩代码。
2. **一个小型、真实的嵌入式项目**（`M5-Utah/`），刷写 ESP32 板并运行**普通演示**：传感器、PWM、声音、手势、无线数据包。

后者**不能**证明前者的超常主张。

---

## 什么才是真正真实的？

| 营销/传说中的主张 | 硬件实际做什么 |
|-------------------|----------------|
| 「Zero Point GPU — 无限 FPS」 | ESP32-S3 上的 2D 波浪模拟 + LCD 绘图 |
| 「无限 Akashic RAM」 | 经 I2C 的舞步垫事件计数器 |
| 「心灵电子放大器」 | 经 MOSFET 的低频方波 |
| 「Med-bed 治愈 DNA」 | 约 61.8 Hz 正弦 + 反相继电器 — **声音电子演示** |
| 「打印你想象的任何东西」 | 手势触发电机步进计数 + UV 继电器闪烁 |
| 「上帝之眼作战室」 | 距离传感器切换状态；ESP-NOW 广播数据包 |
| 「JIT 字节码注入 PSRAM」 | **误导性名称** — 预编译 C++ handler 由 JSON manifest 选择 |
| 「消灭股市」 | 根目录 `README.md` 中的**政治/讽刺叙事** — 非软件功能 |

若有人告诉你仅凭本仓库就能推翻经济学或物理学，**代码并不支持这种说法**。

## 一个下午能验证什么？

用约 $50–200 的 M5Stack 零件和一台笔记本：

1. `py -3 run_studio.py --list` — 六个 manifest 存在；无需魔法。
2. 刷写 kernel → 注入 manifest → **观察并测量行为**（列表见 [Artifact 目录](ARTIFACTS.md)）。
3. 示波器测 PAA 输出 → **7.83 Hz 方波** — 确实是该频率；不是「标量心灵电子能量」。
4. 踩 FSR → **串口日志行** — 可复现。
5. 阅读 `firmware/M5IntegratedKernel/src/artifacts/*.cpp` — **所有行为都在普通 C++ 中**，无隐藏的「Akashic 云」网络调用。

**证伪：** 若注入 manifest 后无串口 ACK、无 UI 变化，则管线失败 — 这是正常工程调试，不是保密。

## 需警惕的红旗（任何 fork 或销售话术）

| 红旗 | 现实检验 |
|------|----------|
| 把「无需焊接」说成「违反热力学」 | 无焊组装是**便利**，不是新物理 |
| JSON/MD 中 0.94 等置信度分数 | **作者自评**，非期刊同行评审 |
| SCIENCE.md 引用与实验不符 | 读原文 — 往往不支持大胆主张 |
| `#include <zpe_core.h>` 类桩代码 | **头文件不存在** — 从未可编译的幻想 API |
| 「相信效果更好」 | `flux_common.py` 中信念不是传感器输入 |
| 无源码的预编译 .bin | 要求匹配的 commit hash + SHA-256；源码在本仓库 |

## 常见质疑的回应

### 「这是骗局吗？」

仓库是**开源叙事 + 开源固件**。读代码无需付费。风险在于第三方转售板子时**硬件加价**或**虚假医疗承诺** — 评估卖家，而非 GPIO。

### 「危险吗？」

**线圈 + 外部电源**与**大声换能器**若接错可能不安全。怀疑者适宜路径：低电压、限流、听力保护。**勿将 med-bed artifact 当作医疗治疗**。

### 「为什么有 General 23 / NYSE 信件？」

`README.md` 中的讽刺与项目神话。不是监管文件。**可部署工程**在 `M5-Utah/` 下。

### 「他们说 JIT 注入 — 是假的吗？」

**术语部分误导。** 真正的 JIT 在运行时编译（如 LLVM、Java 字节码）。此处 **manifest JSON 在 kernel 内已刷写的预编译 artifact 模块中选择**。仍是实用 UX；非新颖计算机科学。

### 「能离线运行吗？」

**可以。** 主机工具与固件可离线工作。`M5-Utah/` 无云依赖。

## 诚实的优点（该肯定处要肯定）

1. **模块化 M5Stack 映射** — 教育用途的合理 BOM（PbHub、FSR、DAC、手势）。
2. **单次刷写多模式 UX** — 合法的创客工作流改进。
3. **清晰的串口协议** — 可在 `flux_protocol.cpp` 中审计。
4. **可分离** — 可 fork `M5-Utah/` 而不背书 UFW 经济主张。
5. **有儿童安全表述** — 见[儿童指南](01-FOR_CHILDREN.md)，明确「非真 med-bed」说明。

---

## 诚实的缺点

1. **命名过载** — 普通嵌入式任务套上超常词汇，易误导买家。
2. **父仓库桩代码** — 27 个项目仍导入虚假 Python/C++ 模块。
3. **SCIENCE.md 置信度分数** — 可暗示未经发生的验证。
4. **Worker 集群不完整** — Command Table ESP-NOW worker 需单独固件，未完整交付。
5. **无签名 manifest** — 注入基于信任的串口；尚无加密认证。

## 怀疑者复现协议（最低成本）

**预算路径：** 仅 CoreS3（约 $50）+ USB 线。

```
git clone <repo>
cd M5-Utah
py -3 -m pip install -r requirements.txt
py -3 run_studio.py --list                    # 验证 manifest
# 编译或获得 .bin 后：
py -3 run_omni_flash.py
py -3 run_studio.py --artifact zero_point_gpu
```

**通过标准：** 串口打印 `ACK: ARTIFACT_ACTIVE`；显示动画。  
**失败标准：** 无 ACK → 记录端口、驱动、板型 env 不匹配 — 发表阴性结果。

## 如何建设性参与

| 应该 | 不应该 |
|------|--------|
| 测量频率、I2C 计数、延迟 | 不读 `zero_point_gpu.cpp` 就驳斥「无限 GPU」稻草人 |
| 索要 manifest + 固件哈希 | 要求步进计数器证明心灵感应 |
| Fork 并诚实重命名 artifact | 把根 README 讽刺与 M5-Utah 工程混为一谈 |
| 将可复现问题报 GitHub issue | 出问题就假定恶意，而可能是 CP210x 驱动 |

## 结论

**M5-Utah 是穿着父档案科幻外衣的真实、有限的嵌入式工具包。**

应将其视为：

- ✅ 教育电子 + 串口部署模式
- ✅ 可用示波器、万用表、串口日志测试
- ❌ 非 ZPE、med-bed 或心灵电子的证据
- ❌ 非金融武器

若只要工程不要传说，使用 `M5-Utah/` 并忽略 27 个同级文件夹即可。
